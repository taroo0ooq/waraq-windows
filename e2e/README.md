# e2e / QA automation — Waraq Windows

**Owner desk:** Stagecraft QA (WRQ-WIN-001 Phase 4)

## What runs in CI

Workflow: [`.github/workflows/playwright.yml`](../.github/workflows/playwright.yml) (required check name: **playwright**)

| Job | Runner | Purpose |
|-----|--------|---------|
| **Windows QA smoke** | `windows-latest` | Real gate: generate fixtures, `dotnet build/test`, 3s app launch smoke |
| **Browser Playwright N/A** | `ubuntu-latest` | Explicit documentation gate — **no browser UI** in MVP |

Script: [`windows-qa-smoke.ps1`](windows-qa-smoke.ps1)

```powershell
# From repo root (Windows + .NET 8; ffmpeg optional but recommended)
./e2e/windows-qa-smoke.ps1 -Configuration Release
```

## Fixtures

`e2e/fixtures/` (generated by smoke script if missing):

- `sample.gif` — tiny animated GIF
- `sample.mp4` — 1s color video (yuv420p)

Set `WARAQ_QA_FIXTURE_DIR` to override fixture discovery for tests.

## Automated coverage

| Layer | Location | Covers |
|-------|----------|--------|
| Unit | `windows/Waraq.Windows.Tests` | Classifier, LocalMediaPath (UNC/URL/size), controller rejects |
| STA integration | `WallpaperIntegrationTests` | Apply/Stop GIF (and video when fixture present) on WorkerW when shell available |
| Smoke script | `e2e/windows-qa-smoke.ps1` | Build + full test + process launch |

## Not automated (residual)

1. Interactive **Browse…** OpenFileDialog clicks (manual matrix)
2. Multi-monitor polish / Explorer restart recovery UX
3. Battery / fullscreen pause (product deferred — not Phase 4 bugs)
4. Browser Playwright specs (N/A until a web surface exists)
5. WinAppDriver / FlaUI full UI drive (optional future)

See matrix: [`docs/qa/WRQ-WIN-001-phase4-qa-matrix.md`](../docs/qa/WRQ-WIN-001-phase4-qa-matrix.md)

## Why not browser Playwright?

Waraq Windows is **WPF + WorkerW**, not Electron/web. Fake browser tests would be theater. The `playwright` workflow name is retained as the hardcoded Agency gate and now executes **real Windows QA smoke**.
